Updated **13 October 2026** for the Paper 26.3 beta. This is a blank test sheet, not a record of passed gameplay tests. The latest documented verification used suite build **757** on Paper 26.3 STABLE **180**. It includes Seasonal Community Efforts, Leaf Litter, the Herbarium botanical journal and optional Mending; startup activation is verified. Startup checks confirmed tool-protection readiness; the boxes below still require actual tester results. The session host records the actual suite build, server build and settings below; previous automated checks do not sign off this session.

**Turn-In update deployed:** F08/F08a/F08b can now test the clickable Accepted Turn-Ins guide and the current 97 default accepted types, including cocoa beans and the later botanical additions. No box is pre-approved by deployment.

**Placed-resource protection deployed:** F13–F16 can now test placements recorded from build 739 onward. Earlier placements are not backfilled. Restart/crash cases still require a separate host-controlled fixture or approved maintenance window.

**Participation tracking deployed:** P11c/P11d can now test qualification while claiming stays disabled. P11e remains **BLOCKED: real map and delivery activation required** until the approved map replaces the unfinished placeholder and staff enables participation claiming.

## Host setup before inviting testers

- [ ] **H01 — Confirm the running build.** Use a complete suite from the canonical build workflow on the maintained Paper 26.3 test server. Record what is actually installed. Enable Forage on the test server and verify CMI, CMILib and the shared library load; verify the economy provider for paid services. Documentation publication does not activate live gameplay.
- [ ] **H02 — Check configuration and storage.** Run `/forage admin check`, `/forage admin balance`, `/forage admin livecheck`, `/forage admin camps worlds` and `/forage debug runtime`. Resolve errors, record warnings, and confirm storage and installed item-protection adapters are ready. A testing-preset warning is expected only when deliberately selected for this session.
- [ ] **H03 — Prepare usable worlds.** Supply travel instructions, an actual Dappled Forest site in the approved Initial Camp world, two different mapped Secondary Camp worlds, and a denied-world fixture. Check mappings rather than assuming the server has `/wild`. Keep the blacklist effective except for deliberate test-only aliases; never copy fixture mappings to live.
- [ ] **H04 — Separate player and staff access.** Use ordinary non-OP tester accounts for the player pass, with `onembcmi.forage.use`, `.shop`, `.stats` and `.camp` under the `onembcmi.forage` prefix. Staff permissions default false, including for OP; grant only the selected staff account or use console. If granting LuckPerms user permissions, target the actual server UUID, including Bedrock accounts.
- [ ] **H05 — Supply fixtures.** Provide camp materials, starter money, accessible gathering patches, plain bonemeal, a matching donor tool and marked Forage treasure for repairs. Prepare advanced tool/level/point fixtures separately from the new-player account. Keep ordinary, renamed and other-plugin items available for comparison. Disable AutoSell initially so it cannot remove intended delivery items.
- [ ] **H05a — Verify scarce starter access.** For OneBlock and Cave, record how an ordinary early player obtains a usable moss, pointed-dripstone or glow-lichen sample when required by an objective. The route must precede the same harvest-dependent objective or reward, not depend on it. Check growth conditions and the exact required tool as well. Mark unavailable routes **BLOCKED**; record any authorized host sample as a test fixture, not proof that a production starter reward exists.
- [ ] **H06 — Prepare recovery evidence.** Run `/forage admin export backup` and wait for completion. Keep the result private. Record a baseline of player stats, money, tool lore/durability and camp registrations. Arrange a second account, Java and Bedrock coverage where supported, and a clean restart window.

## Player walkthrough: first camp and first reward

- [ ] **P01 — Find the instructions.** Away from camp, try `/forage info`, `/forage help`, `/forage guide`, `/forage next` and `/next guide forage`. The docs link opens, text is readable, and the next step explains an Initial Camp in Dappled Forest. Reading instructions does not claim a camp or spend anything.
- [ ] **P02 — Inspect a camp without claiming it.** In Survival, find a vanilla Abandoned Camp or build an equivalent in the host's Initial Camp world. Place a composter and use `/forage camp`. Missing counts should be understandable; the menu must not claim ownership automatically. Ordinary right-click still permits vanilla composting.
- [ ] **P03 — Complete the core physical checklist.** With defaults, provide 1 composter, 24 wool-family blocks (full wool, wool stairs or slabs), 6 fences, 1 lit campfire/soul campfire, 1 chest/trapped chest/barrel and 1 crafting table within 10 blocks horizontally and 6 vertically of the anchor. The Initial Camp anchor itself must be in Dappled Forest. Add missing blocks one requirement at a time and confirm counts update. Complete the additional requirements in P03a too. Trees and lanterns remain optional. A generated Abandoned Camp can still have shortages.
- [ ] **P03a — Complete the additional camp requirements.** Retain P03's composter, 24 shelter positions, 6 fences, 1 storage block and 1 crafting table. Require 1 **lit** campfire/soul campfire, 1 **lit candle position**, 1 **intact straw bed**, 1 **firefly bush**, **2 placed cushions**, **1 water-filled cauldron**, **1 filled flowerpot**, **2 placed stripped log/wood blocks**, and **1 placed banner** in the scan. Check each missing requirement separately. Compare undyed/colored candles, unlit candles and candle cakes: only lit candle blocks qualify, and one to four candles on one block count once. Compare the lit campfire with food cooking and with no food; both must qualify. Try same-color and mixed-color cushion pairs, different filled-pot contents, and plain/custom-patterned standing and wall banners; each valid variant must work. An empty pot must fail. Compare any mix of stripped log/wood blocks against stripped stems, hyphae and bamboo: only stripped logs/wood qualify. Firewood elsewhere inside the footprint must work without touching the campfire. Put the required items only in your inventory or a chest/barrel first, then place them inside the footprint: only the placed features count. The straw bed must have both matching halves inside the scan and count once; ordinary beds must not satisfy it. Existing Abandoned Camp pieces count only when they meet these same rules.
- [ ] **P03b — Check cauldron contents.** Place the required cauldron inside the footprint and compare water levels 1, 2 and 3: each must qualify. An empty cauldron, lava cauldron or powder-snow cauldron must not qualify. A cauldron item or water bucket stored in a chest/inventory must not count as a placed water-filled cauldron.
- [ ] **P04 — Register deliberately.** Use `/forage camp register`, review the confirmation and cancel once; no slot should be consumed. Repeat and confirm in Survival. `/forage camp list` should show one owned Initial Camp and an unfinished Local Introduction. Incidental interactions with other composters must not add registrations.
- [ ] **P05 — Learn workstation access.** Sneak-right-click your owned composter. Tool Shop and Local Introduction should be accessible while global reward services explain their lock. Away from the station, `/forage shop`, `/forage quests` and `/forage dust` should direct you back; merely standing nearby or typing a command does not create a workstation session.
- [ ] **P06 — Buy one starter tool.** Read its supported sources and price, then buy at the workstation. The correct named tool arrives and money is charged once. With insufficient funds or a full inventory, purchase must not take payment without delivery. Keep before/after screenshots for any unexpected result.
- [ ] **P07 — Compare real and ordinary tools.** Break a supported source with the matching Forage tool. `/forage stats` and the tool lore should gain the appropriate progress. Repeat with a normal tool, empty hand and the wrong Forage tool: normal Minecraft behavior may occur, but no Forage gathering credit should be added for those attempts.
- [ ] **P08 — Earn the local introduction.** Gather the displayed target after registration in that camp's world, normally 30 qualifying actions. Another player gathering and your earlier historical actions must not complete it. Keep at least 8 eligible plain organic items for delivery; a tool reward alone does not guarantee the block drops an eligible item.
- [ ] **P09 — Deliver the introduction.** At 30/30, verify reward services remain locked until delivery. Use Local Introduction at your composter to submit the displayed item amount, normally 8. Only eligible current-inventory items are consumed once. Named, enchanted, lore-bearing or PDC-marked items must remain untouched. If blocked, record which item and which requirement the menu identifies.
- [ ] **P10 — Confirm the unlocked camp.** Reopen the workstation. Global reward services should now be available when their own costs and unlocks are met. `/forage next`, status and camp list should agree. Putting items into the physical chest/barrel must not submit them automatically or award progress.
- [ ] **P11 — Complete and claim a quest.** Read a daily objective in Quests & Rewards, perform its actual gathering objective, and return to the workstation to claim. Compare XP, points, money and any described item reward before/after; each enabled reward is credited once and the quest becomes claimed. For item rewards, first try with no empty slots: nothing should be paid, claimed or dropped. Free enough slots and retry. A second click or reopening must not grant it again. Weekly/monthly pages should show their own targets and periods.
- [ ] **P11a — Filter quest status.** In Daily, Weekly and Monthly, compare Show All, Incomplete, Completed and Claimed. Prepare at least one unfinished unclaimed, finished unclaimed and already-claimed quest. Only the matching states should appear: Completed means finished but still unclaimed. Check counts and the selected highlight; opening each category starts on Show All. Switching filters returns to page 1 and preserves quest order. An empty result must explain how to return to Show All. The separate Ready to Claim view must still include completed, unclaimed quests across all periods. Filtering alone must change no balances, progress or claim flags.
- [ ] **P11b — Keep filter navigation and claim guards (host fixture).** Use a host-prepared category with more than 28 matching quests and check 28 per page, Previous/Next, and switching filters from a later page back to page 1. Click an incomplete or already-claimed quest: its details must deliver nothing, and Back must retain the original filter/page. Open a completed quest and choose Claim Reward: the menu closes, normal camp/Local Introduction and once-per-period checks still apply, and reopening the category starts on Show All with the quest in Claimed. An expired visit or invalid camp must not become claimable through filtering.
- [ ] **P11c — Earn participation qualification.** Successfully claim one daily and one weekly quest. Test daily-first and weekly-first on separate accounts, and use a host fixture to span different periods without changing the shared server clock. Completion without a successful claim, a failed claim and monthly claims must not satisfy either requirement. Each player’s progress is separate and must survive reconnect, period rollover and camp/world changes. On a host-prepared load fixture, retained old `claimed: true` daily/weekly records may qualify; completed-only records and missing historical records must not invent credit.
- [ ] **P11d — Keep qualification while the map is unavailable.** With participation claiming disabled, successfully claim ordinary daily and weekly rewards. In Forage → Quests & Rewards, inspect Participation Reward: qualification must still be recorded, the button must explain that claiming is not open yet and progress is saved, and no participation item may be delivered. The current `forage_participation` kit is an unfinished item placeholder, not the promised map; do not enable delivery or mark a map test passed with that placeholder.
- [ ] **P11e — Deliver the participation map once (blocked; approved real map and activation required).** After staff supplies and verifies the real map and enables claiming, use a qualified account to claim manually from Participation Reward at its own complete camp workstation with Local Introduction finished. Qualification alone must not auto-deliver; a remote command, invalid camp, unfinished introduction, expired workstation session or foreign menu must not grant a claim. Check the exact map item and its components. A full inventory or invalid/unavailable template must produce no drop or successful claim. Free space and retry only when the earlier attempt is confirmed to have had no effect. Repeated clicks, reopening, reconnecting, later daily/weekly claims, new periods and another camp/world must not produce a second participation reward. Keep any uncertain transaction reference for staff review rather than replaying it.
- [ ] **P12 — Reconnect and learn the help loop.** Log out safely and return. Camp ownership, completed introduction, progression and claimed quest remain. Test `/forage status`, `/forage limits`, `/forage stats` and `/forage review`; review is read-only. With optional hints off through `/guidance`, explicit `/forage next` still works.

## More player features

- [ ] **F01 — Cover every tool route.** At the workstation, read the tool guide and test each available row below. Record one credited action and one rejected mismatch per row. The last four tools normally unlock when a carried Forage tool reaches tool level 2; bring that tool to the shop. Record staff-supplied fixtures separately.

| Tool (staff give ID) | Example current source | What to observe |
| --- | --- | --- |
| Sickle (`sickle`) | Wheat or configured flora/mushrooms, including red shrubs and shelf mushrooms | Block-break gathering credit |
| Axe (`axe`) | Logs, including poplar; configured fruit blocks | Matching source credit |
| Trowel (`shovel`) | Moss | Moss-family credit |
| Shears (`shears`) | Leaves, including red/orange/yellow poplar leaves | Leaves-family credit |
| Pickaxe (`pickaxe`) | Configured stone/cave blocks | Tool-level shop gate, then matching credit |
| Brush (`brush`) | Configured sand, gravel or clay | Break a matching block; archaeology brushing is not a separate credit route |
| Sword (`sword`) | Host-provided configured gentle creature, such as a cow | Matching melee hit and death while holding the matching Forage tool type |
| Mace (`mace`) | Host-provided configured danger creature, such as a blaze | Same entity rule; avoid unrelated projectile/environmental kills |

- [ ] **F01a — Browse complete sources.** Use `/forage sources` while holding each Forage tool and while empty-handed. Held tools open their full list; otherwise choose a tool. Test `/forage sources shovel` for the Trowel and an invalid ID for clear help. Click Tools & Families entries, the hub's Tools & All Sources button and onboarding's What can I gather? entry. Use every page, go back to the picker and open the public documentation link. Check the source hint on a newly issued tool and on an existing tool after its normal Forage lore refresh; merely opening the guide need not rewrite old lore. Each enabled source appears once with the correct family and action; no reward or workstation access is granted by browsing. Repeat away from camp, with a daily cap reached, in an unavailable world and with a low-durability tool: the source list remains readable while gathering follows its normal guards. Compare two tiers of the same tool; their sources must match.
- [ ] **F01b — Match source action to reward.** Break a listed block with its matching tool, including a Brush block source. Vanilla archaeology brushing, picking up drops and breaking an unlisted crafted block must not grant source progress. For Sword/Mace, land a matching melee hit, receive kill credit within ten seconds and hold the matching tool type at death. Compare projectile-only kills, switching to an ordinary tool before death and waiting beyond ten seconds. Record actual rewards separately from source membership and any cap/world/area/tool-condition pause.
- [ ] **F02 — Check the 26.3 additions.** Try poplar logs and leaves, red shrubs and shelf mushrooms with their matching tools. Saplings and crafted poplar building blocks should not count as gathering sources. Report misleading names/icons or missing configured materials.
- [ ] **F03 — Choose a branch.** Use the workstation branch picker; read the family focus and level gate. The first choice is free. Supported gathering updates that branch's history. Try a locked branch, then a switch during its cooldown or without enough points: rejection should explain the requirement without charging. Read actual configured switch costs before confirming.
- [ ] **F04 — Browse your progress.** Open Tips, tool information and leaderboards through the workstation. Check pagination/back buttons, long lore and your stats against `/forage stats`. Daily XP, weekly XP and lifetime/current-balance boards should not be confused with one another.
- [ ] **F04a — Read Recent Activity anywhere.** Open the hub's Recent Activity button and `/forage recent [page]`; both should show the same personal history, newest first, with category, time and wrapped details. Test the command away from camp, without a camp, and while the host pauses Forage. It must remain read-only and grant no workstation access or rewards. Compare two accounts: each must see only its own entries, and an account without `onembcmi.forage.use` must be refused. Test Previous/Next, Refresh to the latest entries, Back to the hub, Close, invalid/out-of-range page input and an empty history.
- [ ] **F04b — Verify recorded feedback.** Gather successfully and inspect history before the pending chat summary is sent; XP and points must already be recorded without adding extra chat messages. Continue across two chat batches and repeat with host-configured batching off. Observe treasure, level-up, quest progress/reward-ready, branch, turn-in and dust notices when those events occur. Trigger a Forage warning and check its title, reason and next steps; repeating the same warning within 30 seconds must not fill the list with duplicates. Failed or rejected gathering must not appear as earned XP or points.
- [ ] **F04c — Check history retention (host fixture).** With defaults, create more than 25 entries and confirm only the newest 25 remain, eight per page. Have the host verify `messages.batch.recent-retain-limit` stays within 1–100 and `messages.batch.recent-entries-per-page` within 3–20. A Forage configuration reload must retain the current history; disconnect/reconnect and a separately scheduled plugin/server restart must clear it. Saved progression and transaction receipts must remain. Recent Activity must not claim rewards or replace `/forage review`.
- [ ] **F05 — Upgrade and refine a tool.** With host-prepared eligibility, hold the tool in your main hand and use Upgrade Tool. Cancel a confirmation first, then complete one tier upgrade. Costs apply once; XP, uses and legitimate durability remain. Try a supported diamond refinement and a compatible Forage enchant. Shears, Brush and Mace have no diamond variant; locked or incompatible choices explain why.
- [ ] **F06 — Observe the durability lock.** Use a worn fixture down to its configured floor, normally 5 durability. It should stop working with a repair explanation instead of breaking. Record the original tool and lore before repairing; do not use an external repair shortcut.
- [ ] **F06a — Open storage and reach repair while worn.** Hold an otherwise valid Forage tool at 5 durability and normally right-click a chest, trapped chest, barrel, ender chest, any shulker box, furnace, blast furnace, smoker, hopper, dispenser, dropper and brewing stand. Each permitted inventory should open without tool use, damage or repair; gathering and external repair attempts must remain blocked. Compare a host-prepared malformed or externally modified tool: ordinary container access must still fail its integrity check. Sneak-right-click your owned composter with the worn tool and then the invalid fixture; reaching recovery must not be blocked by the held tool, but camp ownership, permissions and readiness still apply, and paid actions must reject invalid tools before charging. Repeat at an unowned composter and a host-protected container: access must not bypass those restrictions. Do not expect sneaking to force vanilla containers open.
- [ ] **F07 — Repair and merge.** At the workstation, hold the tool to keep in your main hand, a matching Forage donor type in your offhand, and a marked Forage treasure in inventory. Review costs and repair preview. A successful confirmation consumes the donor and required treasure once, charges once, repairs to the allowed limit and transfers the configured donor XP. Wrong donor, missing treasure or insufficient funds must leave inputs and balances intact.
- [ ] **F08 — Turn in plain resources.** Open Camp Turn-Ins after completing the introduction. Review and cancel once, then confirm with a mixture of plain eligible organic stacks and named/custom items. Only the planned plain stacks are consumed; custom items, tools and marked treasures remain. Check reduced rewards, the displayed item limit and cooldown. Repeat once with AutoSell enabled and report competition for items without assuming Forage reserves future drops.
- [ ] **F08a — Compare inventory items with gathering sources.** Use the [complete accepted Turn-In item list](/player-guides/plugins/forage/#complete-accepted-turn-in-item-list), also reproduced in the [staff guide](/staff-reference/plugins/forage/#complete-accepted-turn-in-item-list), to compare all six families with the host's actual configuration. Current shipped defaults contain 97 accepted item types, including plain cocoa beans; compare the running catalogue if the host customized it. Check small mushrooms, mushroom blocks/stem/shelf mushroom, moss block/carpet and glow berries as plain accepted items. Compare logs, calcite, saplings, sticks and poisonous potatoes: these must stay untouched with the defaults. Use a bought/traded plain eligible stack and a renamed copy; the first can qualify without tool-gathering provenance, the renamed copy cannot. Camp/Local Introduction locks still apply, and a Turn-In must not grant gathering-quest credit or tool XP. Accepted Turn-Ins opens the inventory-material catalogue; `/forage sources` remains the separate gathering catalogue.
- [ ] **F08b — Browse Accepted Turn-Ins.** Click Accepted Turn-Ins from Camp Turn-Ins. Browse all pages, up to 28 types per page, use Previous/Next, click About Accepted Turn-Ins to refresh, and return to Turn-Ins; each accepted inventory material should appear once with its family. Click Public Turn-In Guide and verify the chat link opens this complete item list. With current defaults, expect 97 types including plain cocoa beans. Read the plain-item and preview guidance, and confirm that merely browsing never consumes items, changes progress or pays a reward. Plain cocoa beans should qualify; a renamed cocoa-bean stack must remain rejected. Have staff temporarily disable an allowed family or alter a material binding on a separate fixture: the reopened catalogue and submission resolver must agree. Try shift-click, drag, number keys, offhand swap and stale-page clicks; no catalogue item may enter the inventory or grant submission authority.
- [ ] **F09 — Craft dust.** Craft standard dust, normally 8 per batch, from the workstation using the displayed money, points and plain bonemeal costs. Test greater dust separately, normally 4 per batch plus marked treasures. Cancelled/blocked trades consume nothing. Renamed/custom bonemeal must not be consumed as plain bonemeal.
- [ ] **F10 — Use dust in the field.** Right-click eligible crops/saplings, including the 26.3 poplar/red shrub/shelf mushroom targets with suitable space/support. A successful pulse consumes one dust, respects cooldown and bounds target selection/bone-meal applications, and directly adds no Forage XP or points. A grown tree can extend beyond the target-selection radius. If no target accepts a pulse, dust is retained; test a protected-boundary fixture separately and expect protected growth to be cancelled. Vanilla random growth may need repeated valid attempts. Record dust and plant changes together; do not expect every plant to grow every time. Legendary dust is a rare treasure outcome, not a guaranteed shop option.
- [ ] **F11 — Check treasure delivery.** On a real treasure roll or a host-controlled fixture, test empty, partial and full inventory. A successful find must fit in inventory, appear once and increment treasure progress once. With no capacity, the find is skipped: no ground drop, queued reward or treasure-stat/quest increment. Staff tool grants have different overflow behavior, so do not use `/forage admin give` to simulate this test. Do not fail a normal short run merely because no rare drop occurs.
- [ ] **F11a — Compare treasure appearance and eligibility (build 754+).** Compare an older genuine non-glowing treasure with a newly delivered ordinary marked treasure: the new find should shine by default without added enchantments, and both must pass the same existing treasure eligibility checks. On a host-controlled fixture, disable `treasures.mark-drops.glint` and create another find; only the future find should lose the shine. Existing items and saved delivery payloads must retain their appearance and identity. A renamed or merely glowing imitation must not qualify. Record any fixture grants separately from natural delivery.
- [ ] **F12 — Check limits without guessing.** Use the host's reduced-cap fixture. Gather until a family cap or chunk exhaustion blocks rewards, then compare `/forage limits` and the explanation. For a capped family try another eligible family; for an exhausted chunk try a fresh chunk. A global gathering cap stops ordinary rewards on every gathering route. Tool wear/uses continue while player/tool XP pause. From build 757, use F12a–F12c for the bounded daily-only exception. Startup is verified; these gameplay cases remain unchecked until observed. Changing camps/worlds must not reset global or family daily usage. Test fresh recorded placements and genuine crop-growth exceptions separately below. Historical placements and creature-spawn origins are not established by the build 739 placement guard; record those farm-loop rates separately.
- [ ] **F12a — Finish only eligible dailies after caps (build 757+).** On the host's fixture, independently reach global XP, global action, family XP and family action caps with `quests.daily-cap-progress.enabled: true`. Keep unfinished current daily action/family/material/biome quests. Correct natural/grown block gathering and a supported creature-action control may advance matching daily objectives up to their target; a new biome needs an eligible gather. Completed/claimed dailies, daily treasure quests, weekly and monthly quests must remain unchanged. Compare player XP, tool XP, Points, treasures, branches, Community Efforts, Herbarium, Local Introduction and lifetime rewarded-action/Mending-unlock totals: none may increase from capped daily-only gathering. Normal permitted drops and wear may continue.
- [ ] **F12b — Keep other blockers and chunk limits (build 757+).** Repeat the capped daily fixture with wrong/ordinary/invalid or safety-locked tools, placed resources, immature crops, cancelled/protected actions, denied worlds, disallowed game modes, missing permissions and unavailable/pending transaction state. No daily credit or chunk allowance may be consumed. Exhausted chunks must still block; an eligible fresh chunk or completed cooldown can allow credit. Record chunk counts: a capped action spends allowance only if it advances a qualifying daily objective, not for a nonmatching source, repeated biome or already-met target. Switching Cave/Pickaxe to Cave/Shears must share the same family cap; world/camp changes must not reset it. Disable the option on the fixture and confirm ordinary cap behavior returns with saved quest progress intact.
- [ ] **F12c — Claim normally and respect rollover (build 757+).** Complete an eligible daily through capped gathering, then return to the owned active workstation after Local Introduction and claim its full configured reward once. Remote/foreign/stale/expired visits, duplicate claims and failed delivery must retain their existing protections. A genuine old, traded or purchased treasure must not advance a treasure-find quest; Turn-Ins must not advance gathering objectives, and their own caps remain unchanged. In a separate approved rollover fixture, confirm the current daily period resets at server-local midnight, with no carryover or repeat claim for the old period. Do not alter the shared server clock. Leave these cases unchecked until the new build is installed and observed.
- [ ] **F13 — Deny placed-block rewards.** Record XP, points, held-tool XP, branch/quest/introduction progress, treasure totals, daily allowance and chunk counts. Place a configured resource with each hand, using an ordinary item/tool, then break it with the correct Forage tool. Repeat with another player as placer, a placer without Forage permission and a host's Creative fixture. Also place while gameplay or that configured family is paused, then re-enable before breaking: the mark must remain effective. Break/re-place repeatedly, including after more than 12 seconds: no listed reward or allowance/chunk count may change from these breaks. The chat throttle must not act as a reward cooldown. Normal allowed breaks/drops/wear remain; a naturally occurring matching block is the positive reward control. A protected/cancelled placement must not mark an otherwise eligible existing block.
- [ ] **F14 — Follow moved and falling blocks.** Push and sticky-pull marked resources within one chunk and across a chunk boundary, with someone other than the placer doing the final Forage break. Include a multi-block line containing both marked and unmarked blocks; each surviving source must carry its own prior status, without overwriting a neighbor's. Verify moved marked blocks remain ineligible and an otherwise eligible unmarked control stays eligible. Check a cancelled move leaves tracking unchanged. Where a piston destroys a block instead of moving it, its old mark must not be copied to another destination. Place sand, red sand or gravel over a drop, let it fall, and break it at the landing position: falling must not clear its placement history. Repeat with another account placing or breaking it.
- [ ] **F15 — Preserve grown harvests.** Plant a supported ageable crop and compare breaking it before maturity with a separate crop that genuinely grows to maturity; the recorded placement blocks rewards until that genuine maturity transition. Repeat natural, player-bonemeal and dispenser-bonemeal growth, including cancelled growth on a host fixture. Grow a tree and check its new resource blocks can earn normal rewards after any next-tick verification. Compare a type-changing growth replacement with same-type bonemeal on placed moss: only a real replacement clears the old mark, so the original moss must stay ineligible. For sugar cane and bamboo, compare newly grown upper blocks with the placed base: upper growth can qualify, the base stays marked. Also place bamboo on the ground, manually add another bamboo above its seedling, then break the base; this placement-driven conversion must not grant rewards. With a host fixture, replace a candidate block again before delayed growth verification and check the new placement mark survives. All usual tool, world, cap and protection checks still apply.
- [ ] **F15a — Compare starter origin with genuine new growth.** Use separately identified bought, traded and reward-issued starter fixtures. Directly place/break each starter as a negative control, then cultivate fresh copies and manually harvest genuine offspring with the matching Forage tool.
