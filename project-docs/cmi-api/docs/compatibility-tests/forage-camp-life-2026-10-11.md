## Deployment status

Activation needs the next authorized synchronized suite build for both maintained servers; configuration reload alone cannot install these checks.

## Requirements

The existing composter, 24 wool-family shelter positions, six fences, one storage block and one crafting table remain required. One campfire or soul campfire must now be **lit**. Pending defaults require one **lit candle block**, one **intact straw bed**, one **firefly bush**, **two placed cushions**, **one water-filled cauldron**, **one filled flowerpot**, **two stripped log/wood blocks** and **one banner** inside the registered footprint.

Undyed and colored candles qualify; candle cakes do not. One to four candles at one position count once. A lit campfire qualifies with or without cooking food. Extinguished or waterlogged candles/campfires do not count. A straw bed counts once from its foot only when its matching head and orientation are also inside the footprint. Ordinary beds, orphan halves and mismatched parts do not qualify. The firefly bush has no night-time or particle condition. These are gameplay requirements, not a claim that every vanilla Abandoned Camp already contains them.

The added decoration defaults are `camp.requirements.cushions: 2`, `water-cauldrons: 1`, `filled-flower-pots: 1`, `firewood: 2` and `banners: 1` under the same `camp.requirements` section. Any two placed `Cushion` entity colors qualify, including a mixed pair, within the loaded footprint. `*_CUSHION` materials are inventory-only items; cushion counting uses the public entity API, while cauldrons, pots, firewood and banners use the block scan. A water cauldron qualifies at any positive level, 1–3. Empty, lava and powder-snow cauldrons are excluded. Partial water use does not invalidate it, but draining the last qualifying water cauldron creates a shortage requiring deliberate revalidation once observed. Flowerpots need any vanilla-valid contents; empty pots do not qualify. Firewood is limited to `STRIPPED_*_LOG` and `STRIPPED_*_WOOD`, including mixed types; stripped stems, hyphae and bamboo are excluded. It may sit anywhere in the normal footprint. Banners may stand or hang on a wall, in any color, plain or patterned. Inventory items, dropped items and chest contents never substitute for placed features.

The guide, counted checklist, onboarding lore, defaults and setting comments explain the additions. Lore is wrapped instead of extending the previous single-line material list. No new fire-spreading, sleep, item-consumption or decoration-reward mechanic is introduced.

## Revalidation and access

On-use validation continues to check the current physical camp before granting workstation actions. The observer also checks affected registered camps after ordinary block changes, light/water interactions and bed departure. Explicit `PlayerFlowerPotManipulateEvent` and `CauldronLevelChangeEvent` observers cover emptying pots and water use. A `Cushion` removal observed through `EntityRemoveEvent` queues a check unless its cause is `UNLOAD`; unloading is not damage. Checks run on the server thread on the next tick, coalesce repeated events, and process at most two footprints per tick. Every footprint chunk must have both its blocks and entity data loaded before any block or cushion scan runs; unavailable entity data cannot be mistaken for zero cushions. No scan loads or generates chunks.

An observed shortfall marks the existing registration for deliberate revalidation, ends its workstation visit, and requests the existing asynchronous persistence path. If the Initial Camp becomes invalid, its owner's Secondary Camp access also pauses. Relighting or replacing the missing feature restores physical readiness, but the owner must confirm revalidation before using the camp again. Registration identity, Local Introduction and Global Forage Progress are retained.

The observer checks resulting world state rather than assuming that every interaction changed a block. Canceled actions and a straw bed that survives leaving it must not invalidate a complete camp. It is not a complete block-history service: damage repaired before the queued check, changes while the footprint is unloaded, or arbitrary plugin edits without events may only be assessed by later on-use validation. Successful previews never cache authorization for a later reward or purchase.

## API evidence and acceptance

Primary discovery used the [Paper documentation index](https://docs.papermc.io/llms.txt). Block-state sampling uses public [Lightable](https://jd.papermc.io/paper/26.3/org/bukkit/block/data/Lightable.html), Waterlogged and [Bed](https://jd.papermc.io/paper/26.3/org/bukkit/block/data/type/Bed.html) APIs. The exact cached Paper 26.3 BETA 174 API identifies `STRAW_BED` with `Bed` data. Runtime inspection confirmed the vanilla straw-bed removal follows bed departure; production code uses the public event and resulting block state rather than server internals. Cushion sampling uses the public [Cushion entity API](https://jd.papermc.io/paper/26.3/org/bukkit/entity/Cushion.html) and [World.getNearbyEntities](https://jd.papermc.io/paper/26.3/org/bukkit/World.html) with the camp bounding box, then requires a valid Cushion that is not removed/dead and whose location is inside that footprint. The scanner first checks block-chunk readiness and [Chunk.isEntitiesLoaded](https://jd.papermc.io/paper/26.3/org/bukkit/Chunk.html); it does not load missing entity data to count decoration. These signatures were verified against the exact cached Paper 26.3 BETA 174 API.
